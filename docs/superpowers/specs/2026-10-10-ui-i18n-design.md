## 0. Bối cảnh & quyết định

### Mục tiêu

- Chốt **thiết kế hình ảnh** cho site đọc và trang quản trị (spec gốc mới chốt chức năng).

## 2. Site đọc đa ngôn ngữ (`blog.oki-dev.xyz`)

### 2.1 Đường dẫn

| Đường dẫn | Nội dung |
|---|---|
| `/` | Trang chủ **tiếng Việt** (cùng nội dung `/vi/`) + script chọn ngôn ngữ (mục 2.4) |
| `/vi/`, `/ja/` | Lưu trữ theo năm, toàn bộ bài |
| `/{vi,ja}/posts/<slug>` | Trang bài viết |
| `/{vi,ja}/tags/` | Danh sách tag (tên theo ngôn ngữ giao diện, kèm số bài) |
| `/{vi,ja}/tags/<khóa>` | Bài theo tag, dạng lưu trữ theo năm |
| `/{vi,ja}/search/` | Tìm kiếm (Pagefind) |
| `/404.html` | Trang 404 chung, thông báo song ngữ, link về `/vi/` và `/ja/` |

`<html lang>` = ngôn ngữ giao diện của trang. Phần nội dung bài có `lang` của bản đang hiển thị (`<article lang="vi">`).

### 2.2 Quy tắc sinh trang bài

Với **mỗi ngôn ngữ giao diện `L` ∈ {vi, ja}** và **mỗi bài có ít nhất một bản `published`**, sinh **đúng một** trang `/L/posts/<slug>`:

- Bản `L` đã đăng → hiển thị bản `L`, `slug` = slug của bản `L`.
- Bản `L` chưa đăng → hiển thị bản còn lại `L'`, `slug` = slug của bản `L'`; đầu bài có thông báo (ví dụ `L = ja`: 「この記事はベトナム語のみです」; `L = vi`: "Bài này chỉ có bản tiếng Nhật").

Danh sách bài (trang chủ, trang tag) dùng cùng quy tắc chọn bản: hiện tiêu đề bản `L` nếu đã đăng, ngược lại tiêu đề bản `L'` kèm nhãn `L'`. Ngày hiển thị là `publishedAt` của bản được hiển thị; sắp xếp theo ngày đó, mới nhất trước.

Vì slug của bản `L'` có thể xuất hiện dưới `/L/`, **slug duy nhất trên toàn site** (cả hai ngôn ngữ) — mục 3.2.

### 2.3 Hai nút chuyển

| Nút | Vị trí | Hành vi |
|---|---|---|
| `[vi\|ja]` | Header, mọi trang | Chuyển sang **trang tương ứng** ở ngôn ngữ giao diện kia (luôn tồn tại theo 2.2); ghi `localStorage.lang` |
| `vi \| 日本語` | Đầu trang bài | Chỉ hiện khi **cả hai bản đều `published`**; dẫn tới `/L'/posts/<slug của bản L'>` |

"Trang tương ứng": trang chủ ↔ trang chủ, bài ↔ trang của cùng bài, tag ↔ cùng khóa tag, tìm kiếm ↔ tìm kiếm. Mỗi trang ghi sẵn URL tương ứng lúc build (thuộc tính `data-alt-url` trên nút).

### 2.4 Ghi nhớ ngôn ngữ (không có CloudFront Function)

- `/` phục vụ trực tiếp trang chủ tiếng Việt (không chuyển hướng ở lần đầu).
- Script inline trong `<head>` **chỉ của `/`**: nếu `localStorage.lang === "ja"` → `location.replace("/ja/")` trước khi hiển thị. Đọc/ghi `localStorage` bọc trong `try/catch` (trình duyệt chặn lưu trữ → hành xử như lần đầu).
- Các trang có tiền tố (`/vi/...`, `/ja/...`) **không** chuyển hướng theo lựa chọn đã lưu — link chia sẻ luôn mở đúng ngôn ngữ.

### 2.5 Trang bài viết

Từ trên xuống: ảnh bìa (nếu có) → tiêu đề → meta `2026-10-12 · #tag … · N phút đọc` → nút chuyển bản dịch (2.3) → thông báo "chỉ có bản …" (nếu có) → nội dung.

- Thời gian đọc: tiếng Việt ~200 từ/phút; tiếng Nhật ~500 ký tự/phút.
- Ảnh bìa: `<img>` có `width`/`height` (lấy lúc build) để tránh nhảy bố cục; giá trị `coverImage` **luôn được escape** khi đưa vào thuộc tính (Kế hoạch 1 ghi nhận regex kiểm tra còn lỏng).

### 2.6 Tag

- Bài lưu **khóa** tag (chữ Latin thường, ví dụ `life`). Tên hiển thị theo ngôn ngữ lấy từ item tag (mục 3.3); thiếu tên → hiện khóa.
- URL dùng khóa: `/ja/tags/life`, hiển thị `#暮らし`.

### 2.7 Tìm kiếm

Pagefind tách chỉ mục theo `<html lang>`: `/ja/search/` tìm trên các trang dưới `/ja/` (gồm cả bài chỉ có bản tiếng Việt), đúng với những gì người đọc thấy ở giao diện tiếng Nhật. Giao diện tìm kiếm dùng component mặc định của Pagefind, chỉnh màu theo biến 1.1.

### 2.8 Chuỗi giao diện

`apps/site/src/i18n/vi.ts`, `ja.ts`: cùng một tập khóa (TypeScript kiểm tra hai file đủ khóa như nhau). Không dùng thư viện i18n.

## 3. Mô hình dữ liệu & API (thay mục 2 spec gốc)

### 3.1 Bài viết

Một item `PK = POST#<id>`, `SK = POST`:

```ts
interface Post {
  id: string;                      // ULID
  tags: string[];                  // khóa tag
  coverImage: string | null;
  createdAt: string;
  updatedAt: string;               // = GSI1SK
  version: number;                 // optimistic lock cho cả bài
  versions: { vi?: LangVersion; ja?: LangVersion };  // ít nhất một bản
}

interface LangVersion {
  slug: string;
  title: string;
  excerpt: string;
  content: string;                 // Markdown, ≤ 180.000 byte UTF-8
  status: "draft" | "scheduled" | "published";
  publishAt: string | null;
  publishedAt: string | null;
  updatedAt: string;
}
```

- Giới hạn nội dung **180 KB mỗi bản** (hai bản chung một item, giới hạn item DynamoDB 400 KB).
- Mọi thao tác ghi tăng `version` của bài. Tab `vi` và `ja` trong cùng trình soạn dùng chung `version` mới nhất nhận về sau mỗi lần lưu.
- `publishedAt` giữ nguyên khi gỡ rồi đăng lại (như Kế hoạch 1).

### 3.2 Slug

- Item `SLUG#<slug>` / `SLUG` chứa `{ postId, lang }`. **Duy nhất trên toàn site.**
- Tạo/đổi slug một bản → transaction: ghi bài (điều kiện `version`) + giữ slug mới (`attribute_not_exists`) + xoá slug cũ của **chính bản đó**.
- Slug tự sinh từ tiêu đề của bản; tiêu đề không có chữ Latin (tiêu đề tiếng Nhật) → slug = `<id viết thường>-<lang>` (ví dụ `01jabc…-ja`).

### 3.3 Tag

- Item `TAG#<khóa>` / `TAG`: `{ key, names: { vi?: string, ja?: string }, GSI1PK: "TAG", GSI1SK: key }`.
- Khóa tag sinh bằng `normalizeTags` hiện có (chữ Latin thường, gạch nối).
- Lưu bài **không** tự tạo item tag. Item `TAG#…` chỉ được tạo/cập nhật qua `PUT /tags/{key}`. Tag được bài dùng nhưng chưa có item = tag chưa có tên (hiển thị khóa).
- `GET /tags` trả về hợp của (khóa tag đang được bài dùng) và (các item `TAG#…`), kèm `postCount` tính từ danh sách bài.

### 3.4 Trạng thái, hẹn giờ & build

- Vòng đời `draft → scheduled → published → draft` (spec gốc 2) áp dụng **cho từng bản** độc lập.
- Lịch hẹn: tên `post-<id>-<lang>`; sự kiện `{ type: "scheduled-publish", postId, lang, publishAt }`; chỉ đăng khi bản `lang` vẫn `scheduled` và `publishAt` khớp.
- **Cần build lại** khi có ít nhất một bản `published` trước **hoặc** sau thay đổi (gồm thay tag/ảnh bìa của bài có bản đã đăng).

### 3.5 API (thay bảng API spec gốc)

| Method | Route | Chức năng |
|---|---|---|
| GET | `/posts` | Danh sách bài; `versions` bỏ `content` |
| POST | `/posts` | Tạo bài với **một** bản đầu tiên: `{ lang, title, slug?, excerpt?, content?, tags?, coverImage? }` |
| GET | `/posts/{id}` | Chi tiết bài, đủ hai bản |
| PUT | `/posts/{id}` | Sửa phần chung `{ tags, coverImage, version }` |
| DELETE | `/posts/{id}` | Xoá cả bài (huỷ mọi lịch hẹn, giải phóng mọi slug) |
| PUT | `/posts/{id}/versions/{lang}` | Tạo hoặc sửa một bản `{ title, slug?, excerpt, content, version }` |
| DELETE | `/posts/{id}/versions/{lang}` | Xoá một bản; là bản duy nhất → `409 INVALID_STATE` |
| POST | `/posts/{id}/versions/{lang}/publish` | `{ publishAt? }` — đăng ngay hoặc hẹn giờ bản đó |
| POST | `/posts/{id}/versions/{lang}/unpublish` | Gỡ / huỷ hẹn bản đó |
| GET | `/tags` | Danh sách tag `{ key, names, postCount }` |
| PUT | `/tags/{key}` | Đặt tên `{ names: { vi?, ja? } }` |
| POST | `/uploads`, GET `/builds/latest`, POST `/builds` | Không đổi |

`{lang}` chỉ nhận `vi` hoặc `ja` (khác → `400`).

**Tài khoản E2E:** cấm `publish`, `unpublish`, `POST /builds` (như cũ); chỉ được sửa/xoá bài mà **không bản nào** đang `published` hoặc `scheduled`; được `PUT /tags/{key}` chỉ với tag chưa gắn vào bài có bản đã đăng.

### 3.6 Lambda Build

Đọc toàn bộ bài + toàn bộ tag (GSI `byUpdated`, `GSI1PK = "POST"` và `"TAG"`), sinh trang theo mục 2. Lọc các bản `published` ngay trong loader.

## 4. Trang quản trị (`admin.oki-dev.xyz`, chỉ tiếng Việt)

Dùng biến màu/font mục 1 (sáng/tối theo hệ điều hành). Trang đăng nhập Cognito Managed Login được chỉnh màu nền tối và logo `~/oki-dev$`.

### 4.1 Thanh trên cùng

`~/oki-dev/admin$` · breadcrumb · **trạng thái build** (`● build ok` / `● đang build…` / `● lỗi` + nút **Build lại**) · "đã lưu HH:MM".

### 4.2 Danh sách bài (`/`)

- Mỗi dòng: tiêu đề (bản `vi`, không có thì `ja`) · nhãn `vi: đã đăng | nháp | hẹn giờ | —` và `ja: …` · tag · thời điểm sửa.
- Lọc theo trạng thái (bất kỳ bản nào), tìm theo tiêu đề cả hai bản.
- **+ Bài mới** → chọn viết bản `vi` hay `ja` trước.

### 4.3 Soạn bài (`/posts/:id`) — 3 cột

```
┌ thanh trên cùng ─────────────────────────────── [ Đăng bản vi ▾ ] ┐
│ [ vi ● đã đăng ] [ ja ○ nháp ]                                     │
├──────────────────┬──────────────────┬──────────────────────────────┤
│ tiêu đề          │ xem trước        │ — riêng bản vi —             │
│ Markdown         │ (giống bài thật) │ slug · tóm tắt               │
│ (CodeMirror 6)   │                  │ — chung cả bài —             │
│                  │                  │ tag · ảnh bìa                │
└──────────────────┴──────────────────┴──────────────────────────────┘
```

- **Tab `vi | ja`** kèm nhãn trạng thái; tab chưa có bản → nút **+ Tạo bản ja**.
- **Cột soạn:** CodeMirror 6, chế độ Markdown, chữ đơn cách — hỗ trợ bộ gõ IME tiếng Nhật ổn định.
- **Cột xem trước:** dùng chung package `markdown` với site đọc.
- **Cột thông tin:** riêng bản (slug tự sinh, sửa được; tóm tắt) / chung cả bài (tag có gợi ý — tạo tag mới thì nhập luôn tên `vi`/`ja`; ảnh bìa).
- **Màn hình hẹp:** < 1100px cột thông tin thành ngăn trượt mở bằng ⚙; < 768px cột soạn và xem trước thành hai tab `Soạn | Xem trước`.

### 4.4 Nút đăng (theo tab đang mở)

| Trạng thái bản | Nút chính | Menu ▾ |
|---|---|---|
| Nháp | **Đăng bản vi** | Hẹn giờ… |
| Hẹn giờ | **Hẹn 08:00 JST** | Đổi giờ… · Đăng ngay · Huỷ hẹn |
| Đã đăng | **Cập nhật bản vi** | Gỡ bài |

Hộp thoại hẹn giờ: chọn múi giờ VN (UTC+7) / JP (UTC+9), hiển thị kèm giờ ở múi còn lại (spec gốc 3.2).

### 4.5 Lưu

- Bản **nháp / hẹn giờ**: tự lưu 3 giây sau lần gõ cuối (`PUT /posts/{id}/versions/{lang}`).
- Bản **đã đăng**: chỉ lưu khi bấm **Cập nhật**.
- Phần chung (tag, ảnh bìa): lưu khi rời ô nhập; nếu bài có bản đã đăng thì sinh build.
- `409`: hộp thoại "Bài vừa được sửa ở nơi khác" → tải lại bản mới / ghi đè.

### 4.6 Ảnh

Kéo-thả hoặc dán → thu nhỏ cạnh dài ≤ 1600px, WebP → `POST /uploads` → upload → chèn `![](url)` tại con trỏ.

### 4.7 Tag (`/tags`)

Bảng khóa · tên `vi` · tên `ja` · số bài; sửa tên tại chỗ.

## 5. Kiểm thử (bổ sung spec gốc 5.4)

- **Unit:** quy tắc chọn bản hiển thị (2.2), sinh URL tương ứng (2.3), từ điển `vi`/`ja` đủ khóa, slug fallback `<id>-<lang>`, vòng đời từng bản.
- **Build với dữ liệu mẫu:** bài chỉ `vi`, chỉ `ja`, đủ hai bản (một bản nháp), tag có/không có tên → kiểm tra số trang và URL sinh ra.
- **E2E site đọc:** `/` hiện tiếng Việt; bấm `[vi|ja]` → sang trang tương ứng; mở lại `/` → tự sang `/ja/`; bài một ngôn ngữ dưới `/ja/` có thông báo; nút `vi | 日本語` chỉ hiện ở bài đủ hai bản.
- **E2E trang quản trị:** tạo bài bản `vi` → thêm bản `ja` → tự lưu từng tab → đổi tên tag; không đăng (spec gốc 5.4).
